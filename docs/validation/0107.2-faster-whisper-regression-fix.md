# 0107.2 — Faster-Whisper Regression Fix

## Root cause

The STT pipeline regressed for three concrete reasons:

1. `faster_whisper` was not declared as an explicit project dependency, so the release Python environment used by the backend did not have the package installed.
2. The backend package `__init__` files created an import cycle:
   - `synapse/audio/__init__.py` re-exported `AudioRuntime`
   - `synapse/speech_adapters/__init__.py` re-exported `SpeechAdapterRuntime` and `FasterWhisperSpeechToTextAdapter`
3. The packaged Tauri backend initially omitted Faster-Whisper's runtime asset bundle, especially:
   - `faster_whisper/assets/silero_vad_v6.onnx`

   That caused release-time `POST /api/audio/transcribe` failures with `NoSuchFile` even though the provider registry exposed `faster_whisper` as available.

The import cycle made `synapse.speech_adapters.runtime` fragile to import, and the missing ONNX asset made the packaged backend unusable for real transcription until PyInstaller collected the provider data files.

## Files changed

- `pyproject.toml`
- `uv.lock`
- `backend/synapse/audio/__init__.py`
- `backend/synapse/speech_adapters/__init__.py`
- `desktop/scripts/build-backend.ps1`

## What changed

- Added `faster-whisper>=1.0.0` to project dependencies.
- Updated the lockfile so the dependency is tracked by the repo.
- Removed runtime re-exports from the `audio` and `speech_adapters` package initializers to break the import cycle.
- Added PyInstaller hidden imports for:
  - `faster_whisper`
  - `ctranslate2`
  - `tokenizers`
  - `av`
  - `huggingface_hub`
- Switched the backend packaging step to collect the full `faster_whisper` package data so the ONNX VAD asset is bundled.
