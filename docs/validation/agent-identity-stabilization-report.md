## Minimum Contract

The runtime has two intentionally different validation layers.

### Registry Config

- `CONFIG.yaml` must exist for direct lookup.
- Folder id is canonical.
- Config `id` may be absent and is then inferred from the folder.
- Config `id`, when present, must match the folder.
- `name` falls back to canonical id.
- Partial configs remain readable by registry for backward compatibility.
- Invalid serialized content raises structured `ValidationError`.
- Filesystem ordering is normalized by sorting folder paths.

### Operational Identity

- Normalized `id` is required.
- `name` must be non-empty after fallback.
- `role` must be non-empty.
- `can_delegate` defaults to `False` and must be boolean when supplied.
- `SOUL.md` and `SKILLS.md` are optional UTF-8 files and default to empty
  strings when absent.
- `MEMORY.md` is not currently composed into `AgentIdentity`.

The runtime has no role enum. A non-empty role string is therefore the actual
contract; no artificial enum was introduced.

## Corrections

- Added shared agent config normalization and structured file loading.
- Rejected folder/config id mismatch in registry and identity runtime.
- Converted malformed config parse failures to `ValidationError`.
- Rejected non-boolean `can_delegate` instead of truthiness coercion.
- Added `can_delegate: bool = False` to `AgentConfig`.
- Seeded complete `artemis` and `researcher` fixtures for identity tests.
- Added factory helpers for deliberately invalid config and optional identity
  files.
- Added dedicated registry coverage.

## Bugs Found

1. Folder/config identity mismatch was silently accepted.
2. Invalid YAML/JSON leaked parser exceptions.
3. String values such as `"false"` could become truthy `can_delegate` values.

The seven original test failures themselves were fixture defects, not runtime
bugs.

## Remaining Risks

- Registry intentionally allows partial configs; consumers requiring an
  operational identity must use `AgentIdentityRuntime`.
- Role values are not governed by an enum. Introducing one requires a separate
  compatibility audit of existing agents.
- `MEMORY.md` exists in agent directories but is not represented in
  `AgentIdentity`.

## Mission and Swarm Impact

Mission and multi-agent orchestration can now rely on deterministic folder-id
resolution and explicit delegation capability semantics. The partial-registry
compatibility boundary was retained because several mission fixtures use the
registry only to verify agent existence before full identity resolution.

Before mission stabilization, fix or migrate its incomplete agent fixtures to
the shared factory. Swarm-style coordination should treat `can_delegate=False`
as the explicit default and must not infer delegation authority from role or
folder name.

Continue domain stabilization from the recorded global baseline.
